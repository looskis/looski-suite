# Authorized combined CRM timeline

Compose a record-scoped timeline for contacts, opportunities and deals. A contact timeline includes its directly anchored logged activities (including authorized merged aliases); it does not infer permission to linked deals. Opportunity/deal timelines include their activities, stage/status transitions, typed task-link lifecycle and ordinary Tasks history for linked tasks. Shared Tasks remains authoritative; ending a link retains historical evidence and does not erase tasks. Every source is independently authorized with current owner/assignment/membership/module policy. Hidden sources produce neither payloads, IDs, counts nor cursor evidence.

Timeline is a read projection over existing owning providers, not a new activity table or duplicate task state. Each event identifies its source kind, stable event ID, recording time and source record; event-specific payloads preserve existing snapshots. Show logged activity occurrence time separately from recording time. Include archived activities and Tasks history with visible labels. Activity snapshots remain subject to current activity/anchor read access, and task snapshots remain subject to current Tasks read access. Parent read access is required even when individual source permissions are absent; missing source permission omits that source.

Use deterministic descending recording-time/source-kind/ID keyset pagination, bounded 1–100, with a cursor tied to the target and visible event. Check cursor visibility on continuation; a revoked/foreign cursor fails closed. A bounded candidate scan skips inaccessible records without returning sparse pages or leaking hidden cursors. Reload starts a new live view; paging is not a frozen export snapshot. Existing operation-specific history remains available.

CRM owns queries over CRM activity/link/transition tables. CRM supplies its linked task IDs in batches of at most 100. Tasks owns the independently scoped history provider and returns only matching events newer than the established merged page boundary. No CRM query reads Tasks tables and Tasks has no dependency on CRM. Contact alias resolution uses the Contacts provider. Task history queries never scan unrelated task records. Candidate authorization/projection is batched, wholly unauthorized sources are omitted before scanning, and each query and application batch is bounded. Stop source history scans once enough visible results establish the merged page boundary.

Expose one consistent timeline query via HTTP/OpenAPI, CLI and MCP, with SSR pages linked from record detail. The UI displays event labels, historical status/task snapshot details and independently permitted links, not raw implementation metadata.

Test interleaving, deterministic pagination without duplicates, activity editing/archive history, status label renames versus transitions, task edits and link end/restore, shared task identity, merged contact aliases, each source grant revoked, reassignment, foreign workspace/cursor, disabled CRM, >100 hidden candidates, no internal task IDs in hidden responses, API/CLI/MCP and browser rendering. Existing focused histories and workflows must remain unchanged.
