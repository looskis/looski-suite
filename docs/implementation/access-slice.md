# Staff administration checkpoint

Schema 9 provides permission catalog, role create/read/edit/archive/restore, member listing and role/state administration across API, CLI, MCP and SSR forms. It reuses suite roles and memberships. `workspace.access.admin` is explicit authority to administer all supported staff grants; `workspace.access.read` separately permits reading the directory and catalog. No role name grants authority. Unimplemented actions/scopes are not assignable; previously reserved delete/export grants were removed pending those operations.

Role and membership mutations lock the workspace, recheck current authority, enforce expected versions and commit audit/replay atomically. A final effective administrator must retain workspace read, access read and access administration across their active roles, with active membership/user and an enabled identity. Concurrent removal attempts cannot each rely on the other role remaining. Removed memberships clear assignments. Restoration uses explicit role IDs; it does not restore historical grants. Archive preserves role assignments but disables their authority.

Lists are bounded and paginated with workspace-scoped SQL projections. Browser member forms retain existing assigned roles outside the displayed catalog page. Unsupported browser scope input returns a bounded 400 response. Permission changes take effect with an already-issued identity token because authority comes from current application records.

Evidence: `make check test` passed. Both upgraded `looski-suite-identity-check` and fresh `looski-access-identity-check` installations passed the complete sequential acceptance suite, including bootstrap, identity, Contacts, Organizations, Tags, Intake and Access. Tests cover supported scopes, stale edits, retries, current-token revocation, removed-member cleanup, concurrent final-admin protection, real foreign-workspace IDs, action-specific scope unions, audit rollback and representative web/API/CLI/MCP calls. Two-axis review findings were fixed and rechecked. The fresh test stack was stopped with its volumes/fixture retained.

Invitations, teams, external memberships and module selection are separate increments. Team scope remains unavailable until its policy and scoped queries exist; customer access cannot be granted through staff role administration. See coverage.md for remaining release gates.
