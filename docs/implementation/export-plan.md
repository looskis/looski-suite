# Permission-checked business export

The first export format is versioned JSON, preserving strings exactly, including identifiers, decimal values, notes and values beginning with spreadsheet formula characters. It is a machine-readable interchange format; it is not a spreadsheet file or a database recovery archive. General custom fields and communications are not implemented, and no export claim includes them yet. Files will require their own byte/metadata representation before file portability is claimed.

Expose export pages through a shared Rust operation, HTTP/OpenAPI, CLI, MCP and browser download. A separate workspace-level `workspace.data.export` grant permits use of the export operation; it never expands the record visibility of the existing per-resource read grants. Every page delegates to the same owning business operation used by ordinary clients. Assigned readers therefore export only their visible records and independently visible relationships. The export capability and module availability are rechecked before releasing each page. Missing resource permissions are explicit failures, not silently omitted datasets.

The request selects a closed, documented collection, optional parent ID, lifecycle selection and bounded cursor. The response includes a format/version manifest, workspace, collection, parent/lifecycle selection, source contract version, records and continuation. Stable IDs, current definitions and histories retain their ordinary public shapes; no direct cross-module SQL or credential/session/audit-payload dumps. Definitions, relationships and revision histories are separate named collections so consumers can follow all continuations instead of receiving silently truncated nested arrays.

Pages are current authorized reads, not a consistent whole-workspace snapshot. Concurrent edits can change later pages, and revocation stops subsequent reads. A client building a package must record each page's manifest, require every requested collection/continuation to succeed, and finalize its file only after completion. A coordinated recovery backup remains the mechanism for consistent full-state recovery.

Verify separate export authority, assigned/workspace intersections, foreign workspace and hidden parent denial, independently scoped relationship projection, disabled CRM, revoked membership/export grant between pages, stable pagination beyond one page, archive selections, string fidelity, documented omissions and identical API/CLI/MCP/browser behavior. Test on fresh and upgraded installations and review against the approved access/module boundaries before marking the export release gate complete.
