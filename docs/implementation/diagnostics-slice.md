# Diagnostic pipeline evidence

The API and worker now emit bounded fixed-schema events to the local ClickHouse HTTP interface. Collection is independently configurable and never gates business readiness. The ingestion credential has INSERT-only access; there is no ClickHouse host port. No arbitrary tracing output is forwarded.

Passed October 13 checks: generated request ID correlates an HTTP mutation with PostgreSQL audit; the route contains parameter placeholders; a hostile unknown path/query is stored as `unmatched`; private input never appears in the operation field; ingestion credentials cannot query rows; twelve valid writes committed during a stopped ClickHouse service in 0.485 seconds; ingestion resumed after restart. The bounded-channel unit test confirms immediate overflow drops and the fixed event schema. Independent standards and spec reviews found no actionable diagnostic issues.

The representative tiny fixture initially used 3,457 bytes in three ClickHouse data parts; the repeated full acceptance run accumulated 165,572 bytes in five parts. A Docker resource snapshot measured ClickHouse at 676.5 MiB, 2.54% CPU and 712 tasks, versus API 58.64 MiB, web 40.69 MiB and worker 6.574 MiB. This is a point-in-time reading during test activity on a 7.75 GiB Docker VM, not an idle benchmark or capacity forecast. ClickHouse is the dominant optional service overhead and can be disabled independently. The complete patched-frontend acceptance suite passed, including the diagnostics outage test (twelve committed writes in 0.48 seconds). Raw diagnostic retention is not automatic; its history is intentionally excluded from encrypted business recovery. Transactional audit remains in PostgreSQL and in the recovery archive.
