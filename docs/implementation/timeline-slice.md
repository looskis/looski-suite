# Authorized combined timeline checkpoint

The combined CRM timeline is a read projection for a contact, opportunity or deal. Contacts show directly anchored activity history across authorized merged aliases. Opportunities/deals compose activity snapshots, independent stage/status transitions, typed task-link events and shared Tasks history. A relation never grants read access. Ending a task link retains history; the timeline includes independently authorized work before and after linking. Archived records and earlier snapshots remain visible under current permissions.

CRM owns its history queries and typed links. Activity and Tasks projections are batched through their owning providers. Entire sources lacking current read permission are omitted before candidate scanning. Tasks receives only the selected record's linked IDs, in batches of at most 100, with its own current assignment scope. Each batch excludes events below the established merged page boundary; unrelated task history is not decoded. Memory holds at most the requested page plus one event between batches.

Ordering is descending recording time, source kind and event ID; activity occurrence time is shown separately. Bounded continuation cursors bind the workspace, canonical target kind/identity and event identity. Every continuation rechecks current target and source visibility. Paging is a live view rather than a frozen export snapshot. Alias and survivor visibility remain independent. Schema 23 adds an additional history ordering index; existing source-specific histories remain authoritative.

API/OpenAPI, CLI, MCP and SSR expose the same query. Record detail pages link to the timeline; SSR renders historical activity/task content and status labels with independently authorized source links. The browser presents retained/archived states and earlier-page navigation.
