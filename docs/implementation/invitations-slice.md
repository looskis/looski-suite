# Staff invitation checkpoint

Pending invitations retain the recipient Auth email, original inviter identity/membership, role IDs and versions, expiry, nonce, and acceptance/revocation state. Purpose-bound private links are reconstructed only for authorized administrators. Contacts remain unrelated to authentication proof. Acceptance checks the currently confirmed provider email, current inviter/role authority, active identity/membership, explicit recipient consent, wall-clock expiry after lock waits, and the 50-role membership limit. It atomically creates the suite identity mapping/membership when needed, grants roles, records history and binds retries without storing bearer tokens. Removed memberships cannot be restored by old links.

Administrators can copy a link or explicitly queue email delivery. Typed PGMQ jobs recheck authority and invitation state, provision an unconfirmed provider identity only when absent, and request a recovery email. Existing passwords remain unchanged until their owner explicitly replaces them. The same-origin callback preserves invitation context across email proof and password setup; account creation alone grants no workspace access. Delivery retries external failures with bounded backoff, and operators can inspect or resume blocked/exhausted work through Jobs. Delivery is at least once; it is not a guarantee of mailbox receipt.

HTTP, CLI, MCP and browser interfaces cover administration, preview, acceptance, revocation and delivery. Tests passed current-email proof, wrong/unconfirmed recipients, role/inviter changes, expiry and lock-boundary expiry, removed memberships, 50-role union, concurrent retry, atomic rollback, invalid browser drafts/action intents, CLI/MCP mutations and local SMTP onboarding/outage behavior. Standards/spec review findings were resolved. Full fresh/upgraded regression initially exposed a service-restart configuration issue; the common configuration now supplies the derived mail-enabled setting. A fresh fixture was safely rebuilt after an observed schema/image mismatch. Both installations subsequently passed the complete acceptance suite, including invitation creation/acceptance/revocation, CLI/MCP mutations, browser consent, new/existing identity mail, SMTP failure/retry and current-authority delivery checks. Static checks, Rust/Python tests and production builds passed. Public external SMTP, Cloudflare callbacks and hosted-mode evidence remain separate open gates.

The migrator now contains its migration sources as built image content, avoiding later checkout files being picked up on rerun. Applied migration files remain immutable. This and all remaining slices will be included in the user's requested single signed commit.
