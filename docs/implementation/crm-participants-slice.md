# CRM participants checkpoint

Schema 13 introduces separate opportunity/deal contact and organization associations. Stable association IDs retain their original workspace-qualified reference. Role labels are user-defined metadata, not permission grants. End/restore replaces destructive removal; immutable association snapshots retain edits, primary replacements and lifecycle history alongside the transactional audit.

Participant reads intersect current CRM parent scope with independent Contacts scope. Contact aliases additionally require visibility of both original and survivor. Lists scan bounded candidate batches until a complete visible page is available; public cursors contain only visible association IDs. Merge-induced canonical duplicates preserve individual labels/history. Add/restore rejects visible canonical duplicates without exposing inaccessible alias associations.

Primary promotion/replacement requires workspace-wide read of that reference type uniformly, including when no prior primary exists. Scoped users can demote or end an already visible primary. Omitted primary/state edits preserve their values. Saved promotion retries recheck the broader authority as well as current parent/reference access. A primary replacement appends the demoted association's history in the same transaction.

Mutation reference resolution is owned by Contacts. It shares the existing contact-merge advisory lock, locks original/canonical rows in order (or the organization row), then rechecks visibility, archive state and canonical identity. The locks live through commit. CRM/access workspace locks use `FOR NO KEY UPDATE` to retain writer serialization while permitting FK key-share locks for concurrent Contacts audit insertion. This avoids the opposite workspace/reference lock order during follow-up writes.

API, CLI, MCP and SSR forms expose list/add/edit/end/restore/history. Browser forms retain rejected selections, role labels, primary/state options, expected version and idempotency key; unsupported option values return 400 without mutation. History resolves the current authorized participant while retaining original association metadata.

Verification: static checks and unit tests pass. Full sequential acceptance passes on both the upgraded schema and a fresh isolated installation, covering all four participant types, hidden batches spanning multiple internal pages, alias privacy, primary scope/replay, archive retention, audit rollback, browser draft/conflict behavior, forced archive/merge/reassignment overlaps, concurrent primary edits and actual foreign-workspace constraints. Standards/spec review findings on reference locking and malformed forms have been addressed. This is not the completed CRM release; Tasks, activity/coordination configuration and remaining release gates follow.
